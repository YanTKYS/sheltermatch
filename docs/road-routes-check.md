# 道路に沿った参考経路の確認記録

レビュー用HTMLへ追加した「道路に沿った参考経路」（`ENABLE_ROAD_ROUTES = True`）を、実際の道路データと
架空の要支援者データで確認した記録。

## 0. 確認の経緯と、確認できたこと・できていないこと（重要）

確認は次の順に行った。

1. **開発環境（サンドボックス。Google Colabではない）での確認**
   この環境は外向き通信が制限されており、**OpenStreetMap の Overpass API・Nominatim へ接続できなかった**
   （接続時にプロキシが 403 を返す。BODIK・地理院タイル・unpkg も同様）。そのため、OSMnx による直接取得は
   ここでは確認できず、道路データは次の代替手段で用意して、経路の算出・表示・結果CSVへの影響を確認した
   （第1〜7節はこの環境での確認結果）。

   | 本番（Notebook） | 開発環境での代替 |
   | --- | --- |
   | OSMnx が Nominatim から糸満市の行政区域（OSM relation 4559181）を取得 | Overture Maps（2026-08-19.0）の divisions にある同じ行政区域（出典: OSM relation 4559181）|
   | OSMnx が Overpass API から取得範囲の徒歩用道路を取得（`graph_from_polygon(network_type="walk")`） | Overture Maps の transportation（OSM の way を分割した道路データ。形状・接続は OSM のもの）を OSM XML へ変換し、OSMnx の `graph_from_xml` で読み込んで、Notebook と同じ取得範囲で切り出し・最大連結成分に限定 |

2. **その後の Google Colab での実機確認**
   実際の Google Colab で `ENABLE_ROAD_ROUTES = True` として実行し、次を確認した。
   - OSMnx による Nominatim・Overpass API からの道路データ取得に成功（取得時間 約26.4秒）
   - 道路に沿った参考経路の算出に成功（`road_routes.status = "ok"`）
   - 経路情報を含む `sheltermatch_review.zip` の生成に成功

確認済みの範囲は、確認した環境ごとに次のとおり。

| 項目 | 確認状況 |
| --- | --- |
| OSMnx による道路データの取得（Nominatim・Overpass API） | **Google Colab で確認済み**（取得時間 約26.4秒） |
| 道路経路の算出・経路情報を含むレビューZIPの生成 | **Google Colab で確認済み**。開発環境でも Overture Maps（OSM由来）の道路データで確認 |
| 経路の正しさ（最短距離・道路の形に沿うこと）、表示できない場合の扱い、結果CSVが変わらないこと、処理時間・容量 | 開発環境で確認（第3〜7節） |
| 候補1を自動選択して道路経路を初期表示する画面の動作 | 開発環境で、`file://` で開いた自動ブラウザテストにより確認（第5節）。**この修正を含めて Colab で作り直したレビューZIPでは未確認** |

まだ確認していないこと・注意点:

- 候補1の自動選択を含む最新の画面を、Colab で作り直したレビューZIPで開いての確認
- 開発環境で使った Overture の変換は OSMnx の徒歩用フィルタ（motorway・cycleway・foot=no・access=private の
  除外）に合わせたが、Overpass から直接取得した道路と本数が完全に同じとは限らない。第3・7節の数値は
  開発環境での値で、Colab で取得した道路データでの値ではない
- 開発環境では、背景地図（地理院タイル）・避難所一覧（BODIK）・Leaflet（unpkg）も従来の確認と同様に代替した
  （背景地図は検証用に道路の線を描いた画像で、国土地理院の地図ではない。Leaflet は npm の公式配布物を
  使い、SHA-256 の照合は本体のコードがそのまま行った）
- 実際の要支援者データでは確認していない（架空データのみ）

なお、Notebook は Colab 実行時に `src/` を GitHub の `main` から取得する。通常の利用では、変更が `main` に
取り込まれてから道路経路を使えるようになる（`main` 側のモジュールが古いと、Notebook のモジュール互換性
チェックで止まる）。

## 1. 手順（再現方法）

```bash
# 1) 糸満市周辺の道路データ（Overture Maps / OSM由来）を取得し、OSM XML へ変換
python3 experiments/road_routes/overture_to_osm_xml.py /tmp/road_data
# 2) 架空の入力データ（避難所・確認用の要支援者・市内の1,000人・ハザード区域）を作る
python3 experiments/road_routes/make_test_inputs.py /tmp/road_data /tmp/inputs
# 3) Notebook のセルをそのまま実行（--code origin/main で変更前のコードも実行できる）
python3 experiments/road_routes/run_notebook_check.py --out /tmp/run_on \
    --residents /tmp/inputs/residents_cases.csv --hazard /tmp/inputs/hazard_cases.geojson \
    --shelters /tmp/inputs/shelters.json --road-data /tmp/road_data --road-routes on --inject-island
# 4) レビューZIPを file:// で開いて画面を確認（外部へは一切出られない状態で開く）
python3 experiments/road_routes/check_review_offline.py /tmp/run_on/sheltermatch_review.zip --mode on
```

`run_notebook_check.py` は Notebook のセルを書き換えずに順に実行し、Colab固有の部分（アップロード・
ダウンロード）と、この環境から接続できない外部サービスだけを差し替える。外部へのリクエストはすべて記録する。

## 2. 道路データ

| 項目 | 値 |
| --- | --- |
| 行政区域 | 糸満市（OSM relation 4559181）。領海を含み約1,073km² |
| 取得範囲 | 行政区域＋約2km（約1,370km²、輪郭の頂点49）。要支援者の座標は使わない |
| 道路データ | 徒歩用の道路 14,264本（Overture segment）→ OSMnx のグラフ ノード13,912・道路21,294本 |
| 取得時に外部へ送る情報 | 行政区域ID `R4559181` と、上の取得範囲のポリゴンだけ |

実際の通信を試した確認（`--road-source network`）でも、外部へのリクエストは
`https://nominatim.openstreetmap.org/lookup?osm_ids=R4559181` の1件だけだった（403で失敗）。

## 3. 経路の正しさ

| 確認 | 結果 |
| --- | --- |
| 最短距離を networkx の最短経路と照合（ランダムな247組） | 全組一致（差0m） |
| 経路の線の長さ＝表示する道路上の距離 | 全組一致 |
| 経路の始点・終点＝道路上の接続点 | 247/247 |
| 選んだ接続の組が、接続候補の全組み合わせの中で最短 | 違反0組 |
| レビューHTMLに埋め込んだ経路の全頂点（2,978本・63,292点）と道路の線との距離 | 最大0.075m |
| （道路上＋接続部分）÷直線距離 | 中央値1.30・最小1.00・最大4.21 |

経路は道路の線の形（OSMの折れ点）をそのまま使っている（道路の分岐点どうしを直線で結んだ形ではない）。

確認中に見つけて直したこと:

- 取得範囲の外縁近く（市外）の地点で、範囲外の道路が切れているために実際より大回りの経路になっていた。
  地点が糸満市から1kmより外にある場合は算出しない（「取得範囲の端に近い」と表示する）ようにした
- 地点の最も近くにある歩道の線が、すぐ脇の車道と遠くでしかつながっていない（OSMでは歩道・上下線が
  別々の線として描かれることが多い）ために、直線70mの相手へ道路上1,387mの大回りになる例があった。
  最も近い道路から20m以内の差にある道路も接続候補とし、その中で全体が最短になる組み合わせを選ぶように
  した（同じ例は道路上129m。上限の150mは維持）
- 本人側と避難所側が道路上の同じ点に接続する場合（道路上0m）に、HTML作成前の照合で止まっていた。
  「道路上の同じ地点に接続」と表示するようにした

## 4. 表示できない場合の確認（確認用の要支援者 `residents_cases.csv`）

| 要支援者 | 条件 | 結果 |
| --- | --- | --- |
| C01〜C03 | 市街地・郊外（通常） | 候補1〜3すべて経路を表示 |
| C04 | 海上（道路まで1km以上） | 「本人の地点から150m以内に道路データがありません」。経路を描かない |
| C05 / C06 | 座標なし / 座標が範囲外 | 候補が無いため、線も経路も描かない |
| C07 | ほかの道路とつながっていない架空の道路の近く（検証用に追加） | 「道路データ上で…つながっていません」。経路を描かない |
| C08 | 道路から約450m離れた架空避難所の近く | その候補は「避難所の地点から150m以内に道路データがありません」 |
| C09 | 糸満市外（取得範囲の端） | 「取得範囲の端に近いため算出していません」 |

いずれの場合も、直線を道路経路として表示することはない（直線は従来どおり破線で表示）。

## 5. 画面の確認（file:// で開いて操作）

`check_review_offline.py` で確認した（Chromium。ブラウザの通信をすべて到達できないプロキシへ向けて
外部に出られない状態にし、ページからの file:// 以外への通信の試みも記録）。

| 設定 | 結果 |
| --- | --- |
| 経路あり | 62/62 項目OK |
| 経路を作成しない（既定） | 16/16 項目OK |
| 道路データの取得に失敗 | 17/17 項目OK |

主な確認項目: 要支援者を選ぶと候補1が選択状態になり、その経路・接続部分・経路情報をすぐに表示／
候補1の経路を算出できない場合は候補1のまま理由を表示（候補2・3へ自動で切り替えない）／「次へ」や一覧で
別の要支援者へ移ると候補1に戻る／候補1〜3を選ぶとその候補の経路を1本表示し、候補ごとに異なる経路／
経路の表示切替をオフにすると道路経路と接続部分だけを消す／経路を作成しない設定・作成できなかった場合は
従来どおり候補を自動で選択しない／
道路経路は実線・直線は破線・接続部分は点線／道路上の距離と接続部分の長さを分けて表示／地図と候補表の
大きさが経路表示で変わらない／ハザード列が直線についての判定である旨の注記／経路の表示切替／検索・
前後移動・ハザード表示切替・地図の拡大とドラッグ／出典（国土地理院と OpenStreetMap を分けて表示）／
外部通信なし・JavaScriptエラーなし。

## 6. 結果CSVが変わらないこと

変更前のコード（`origin/main`）と同じ入力で実行し、`assigned_shelters.csv` をバイト単位で比較した。

| 入力 | 経路OFF | 経路ON | 取得失敗 |
| --- | --- | --- | --- |
| 確認用の要支援者9人（ハザード判定あり） | 一致 | 一致 | 一致 |
| 性能確認用の1,000人（`experiments/performance/residents_1000.csv`） | 一致 | 一致 | — |
| 市内の道路近くの架空の1,000人 | 一致 | 一致 | — |

経路OFFのレビューZIPは、`review.html` 以外のファイル（背景地図・ハザード画像・Leaflet等）が変更前と
バイト単位で一致し、`review.html` に埋め込むデータの違いは `"road_routes": null` の追加だけだった。

## 7. 1,000人・候補3件での処理時間とZIP容量

避難所は架空の56か所。時間は開発環境（サンドボックス）での実測で、Colab での値ではない。

| | 市内の道路近くの1,000人 | 性能確認用の1,000人 |
| --- | --- | --- |
| 経路（延べ） | 3,000件 | 2,964件 |
| 算出できた | 2,978件 | 1,658件 |
| 算出できなかった | 22件（道路から離れた架空避難所） | 本人側150m超 774件・市外 510件・避難所側 22件 |
| 経路計算の時間 | 約3秒 | 約2秒 |
| 道路経路セル全体（※） | 約15秒 | 約14秒 |
| レビューZIP（経路OFF → ON） | 472KB → 850KB | 469KB → 785KB |
| review.html（経路OFF → ON） | 1.6MB → 3.6MB | 1.6MB → 3.3MB |

※ osmnx の導入確認（約3秒）と、道路データの読込（Overpass の代わりに OSM XML を読み込む時間、約8.5秒）を
含む。Google Colab で OSMnx により実際に道路データを取得した時間は約26.4秒だった（第0節）。

性能確認用の1,000人は、糸満市を含む矩形に一様に散らばる架空データのため、海上・農地・市外の点が多く、
算出できない件数が多い。3.6MB の review.html も Chromium で約0.5秒で開け、候補を選んでから経路が表示される
までは約0.1秒だった。
