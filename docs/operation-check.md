## 発見した問題・修正した問題

1. **【修正済み】要支援者一覧CSV・避難所フォールバックCSVで、0件選択時も「1つだけ選択してください」と
   表示されていた**
   - 現状（修正前）: `if len(uploaded) != 1: raise RuntimeError("...は1つだけ選択してください。")`
     という判定のため、ファイルを1つも選択しなかった場合にも「1つだけ選択してください」という、
     複数選択時と同じ文言が出ていた。0件と複数選択は原因が異なるため、利用者が次に何をすべきか
     一瞬分かりにくい。
   - 修正: 0件の場合は「アップロードされませんでした。ファイルを1つ選択してください。」、複数選択の
     場合は従来どおり「1つだけ選択してください。」と、原因ごとに文言を分けた（`sheltermatch.ipynb`
     のみ。`address_geocode.ipynb`は元から0件/複数を区別済みだった）。
2. **【修正済み】ハザードZIPを複数アップロードしたとき、1ファイルの読込失敗で全体が停止していた**
   - 現状（修正前）: `for hazard_filename, hazard_bytes in uploaded_hazards.items(): ... layer =
     load_hazard_upload(...)` の中で例外がそのまま伝播するため、5ZIP中1つでも形式不正・
     有効なポリゴン0件だった場合、既に正常に読み込めていた他のZIPの分もまとめて失われ、
     生のtracebackで停止していた。
   - 修正: `load_hazard_upload`の呼び出しをファイルごとに`try/except`で囲み、失敗した場合は
     「このファイルの読込をスキップしました（詳細: ...）」と表示してそのファイルだけ読み飛ばし、
     残りのファイルの処理を続けるようにした。全ファイルが失敗した場合は、従来どおり
     「有効なハザード区域を1件も読み込めませんでした」で停止する（動作・メッセージは変更なし）。
3. その他、上記の一覧で確認した範囲では、意図せず処理が続行する・情報不足で次の操作が分からない
   といった問題は見つからなかった。
