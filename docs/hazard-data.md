# ハザードデータの取得・利用手順

この文書は、sheltermatchでハザード判定に使用するデータについて、どこから取得し、どのファイルを選び、
Notebookへどう投入し、結果をどう読むかをまとめた実務手順書です。実装の内部設計は
`docs/project-status.md` を参照してください。

## 1. 前提

- ハザードデータ本体（GeoJSON・Shapefile ZIP等）はこのリポジトリへ保存しません。使用するたびに、
  国・県等の公式配布元から取得してNotebookへアップロードします。
- ハザード判定は、上の「利用者設定」で `ENABLE_HAZARD_CHECK = True` にした場合のみ実行されます。
- 洪水・土砂災害・津波・高潮など、複数のハザードデータを1回のアップロードでまとめて選択できます。
- ハザード判定は避難先の自動決定や候補の自動除外・順位変更には使いません。距離順の候補とは別の
  参考情報として出力し、最終的な避難先の判断は職員が行います。
- 要支援者地点・候補避難所地点とハザード区域の位置関係に加えて、両地点を結ぶ直線とハザード区域との
  交差判定も行いますが、これは道路経路上の判定ではなく、単純に2点を結んだ直線による判定です。

## 2. 対応している入力形式

現在のNotebook（`sheltermatch.ipynb`）は、以下の入力形式に対応しています。

| 形式 | 説明 |
| --- | --- |
| GeoJSON単体 | `.geojson` ファイルをそのままアップロード |
| GeoJSONを含むZIP | ZIP内のディレクトリ構造に関わらず `.geojson` を再帰的に探索して統合 |
| Shapefileを含むZIP | ZIP内の `.shp`（`.shx`/`.dbf` が揃っているもの）を再帰的に探索して統合 |

**Shapefileは、利用者が `.shp` / `.shx` / `.dbf` 等を個別に選んでアップロードする運用ではありません。**
国・県等が配布する公式ZIPをそのまま1つのファイルとしてアップロードしてください。ZIPの展開や、
GeoJSONへの事前変換は不要です。ZIP内に複数のGeoJSON・Shapefileレイヤーが含まれる場合も、
Notebook側ですべて自動的に読み込んで1つのハザードデータへ統合します。

### ジオメトリの扱い

区域判定はPolygon / MultiPolygonのみを対象とします。読み込んだジオメトリは次のように扱います。

| ジオメトリ | 扱い |
| --- | --- |
| 有効なPolygon / MultiPolygon | 一切変更せずそのまま使用（`make_valid()` もかけません） |
| `is_valid=False` のPolygon / MultiPolygon | `shapely.make_valid()` で直してから使用 |
| 空・欠損のジオメトリ | 区域判定対象外 |
| Polygon / MultiPolygon以外（LineString等） | 独自に面へ変換せず区域判定対象外 |

公式配布データには、自己交差等で `is_valid=False` になっているポリゴンが実際に含まれています。
糸満市で使用する公式11ZIP（津波LEVEL1〜7 / A33 / 高潮 / A31a 2種類、全182,424件）を
`experiments/hazard_geometry_audit.ipynb` で調べたところ、**1,354件**が該当し、その**全件**が
`make_valid()` でPolygon / MultiPolygonへ復元できました（復元された面積は合計約175,085,405㎡）。
復元前後で候補避難所地点の判定に**3件**の差が出たため、本体で直してから使うようにしています。

直した結果がGeometryCollection（面と線が混ざったもの）になる場合は、Polygon / MultiPolygon成分
だけを使います。区域として使える形にならなかったものは、従来どおり区域判定対象外です。

直した行も、元の `hazard_type`（A31aの詳細カテゴリ・A33の現象種類/区域区分・津波の浸水深区分・
高潮のカテゴリ）をそのまま引き継ぎます。種別・カテゴリを再解釈することはありません。

読込時には、不正なジオメトリが何件あり、そのうち何件を直して採用し、何件を除外したのかを
まとめて表示します。

## 3. 洪水データ（国土数値情報 A31a）

- **取得元**: 国土交通省 国土数値情報「洪水浸水想定区域データ（河川単位、A31a）」
  - 一覧ページ: <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A31.html>
    （このページから最新年度の配布ページへ進みます。年度ごとにURL末尾の年が変わるため、年度固定の
    URLは記載しません）
- 都道府県として **沖縄県** を選び、配布形式は **GeoJSON版を推奨** します（Shapefile版も
  sheltermatchで読み込めますが、GeoJSON版の方がファイル構成がシンプルです）。
- 今回実機確認した例（都道府県・年度によりファイル名は変わります）:
  - `A31a-25_47_10_GEOJSON.zip`
  - `A31a-25_47_20_GEOJSON.zip`

  ファイル名中の年度・都道府県コード部分は年度更新のたびに変わるため、これらを固定のファイル名として
  扱わないでください。ファイル名末尾の河川区分だけが意味を持ちます。

  | 河川区分コード | 意味 |
  | --- | --- |
  | `_10_` | 洪水予報河川・水位周知河川 |
  | `_20_` | その他の河川 |

  sheltermatchはこのコードから、入力なしで自動的に次のように認識します。

  - `_10_` → `洪水（洪水予報河川・水位周知河川）`
  - `_20_` → `洪水（その他の河川）`

- 国土数値情報側のZIPには、計画規模・想定最大規模・浸水継続時間・家屋倒壊等氾濫想定区域（氾濫流／
  河岸侵食）等のデータがサブフォルダに分かれて含まれています（配布ZIP内部のフォルダ区切りが `/` /
  `\`（バックスラッシュ）のいずれであっても、sheltermatchが展開時に `/` へ正規化するため、どちらの
  形式でも同じように認識できます）。sheltermatchはこのサブフォルダ名をカテゴリとして保持するため、
  河川区分に加えて詳細な区分も `hazard_type` から失われません。例えば `_10_`（洪水予報河川・水位
  周知河川）のZIP内に `10_計画規模` / `20_想定最大規模` / `30_浸水継続時間` / `41_家屋倒壊等氾濫
  想定区域_氾濫流` / `42_家屋倒壊等氾濫想定区域_河岸侵食` のサブフォルダがある場合、次のように
  `hazard_type` へ保持されます。

  ```text
  洪水（洪水予報河川・水位周知河川）:10_計画規模
  洪水（洪水予報河川・水位周知河川）:20_想定最大規模
  洪水（洪水予報河川・水位周知河川）:30_浸水継続時間
  洪水（洪水予報河川・水位周知河川）:41_家屋倒壊等氾濫想定区域_氾濫流
  洪水（洪水予報河川・水位周知河川）:42_家屋倒壊等氾濫想定区域_河岸侵食
  ```

  カテゴリ名は公式ZIP内のフォルダ名をそのまま使用します（番号の削除や名称の変換は行いません）。

## 4. 津波データ（沖縄県 津波浸水想定図）

- **取得元**: 沖縄県地図情報システム「オープンデータ一覧」
  - <http://gis.pref.okinawa.jp/OpenData/>
- 沖縄県では、浸水深別に **LEVEL1〜LEVEL7** のShapefile ZIPが公開されています。
- 今回実機確認した例:
  - `level1_1cm-30cm.zip`

  このファイルは展開せず、そのままアップロードしてください。
- sheltermatchはファイル名（`level1`〜`level7`）から入力なしで **津波** と自動判定します。
  Shapefile内部に `分類` 属性がある場合は、その値をポリゴンごとの詳細分類としてそのまま保持し、
  `津波:0.01m以上0.3m未満` のような `hazard_type` になります。
  **LEVEL番号から浸水深を独自に推測することはせず、公式データ内の `分類` 属性を優先します。**
- 今回はLEVEL1のみ実機確認していますが、沖縄県ではLEVEL1〜LEVEL7が同様の形式で公開されています。

## 5. 高潮データ（沖縄県 高潮浸水想定区域図）

- **取得元**: 沖縄県「高潮浸水想定区域図」（土木建築部海岸防災課）
  - <https://www.pref.okinawa.jp/machizukuri/kaigankasen/1013605/1040838.html>
    （琉球諸島沿岸高潮浸水想定区域の指定案内ページ。糸満市を含む対象市町村と、GISデータを沖縄県
    オープンデータカタログで公開する旨が案内されています。まずこのページを確認してください）
  - GISデータ本体は、上記ページから案内される **沖縄県オープンデータカタログ** で公開されます。
- **2026年8月27日**、水防法に基づき「琉球諸島沿岸における高潮浸水想定区域」が沖縄県により新たに
  指定・公表されました。糸満市もこの対象に含まれています。
- 今回実機確認した糸満市データの例（この新しい指定に基づくデータです）:
  - `47007_takasiosinnsuisoutei_22itoman.zip`

  このファイルは展開せず、そのままアップロードしてください。

  > **注意**: 沖縄県オープンデータカタログ・BODIK等には、平成18・19年度作成の旧い高潮浸水予想図
  > （例: `data.bodik.jp/dataset/okinawa-dpf_okinawa_pref` 内の「高潮浸水予測図」リソース）も
  > 別途登録されています。今回対象とする2026年8月27日指定の高潮浸水想定区域図とは別のデータなので、
  > 取得時にデータの作成年度・指定根拠を確認し、混同しないようにしてください。
- sheltermatchはファイル名から入力なしで **高潮** と自動判定します。ZIP内部には「最大浸水深」
  「浸水継続時間」の2種類のレイヤーが含まれており、単なる `高潮` に統合せず、それぞれを区別して
  `高潮:最大浸水深` / `高潮:浸水継続時間` として保持します。

## 6. 土砂災害データ（国土数値情報 A33）

- **取得元**: 国土交通省 国土数値情報「土砂災害警戒区域データ（A33）」
  - 一覧ページ: <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A33.html>
    （このページから最新年度の配布ページへ進みます。A31a同様、年度固定のURLは記載しません）
- 都道府県として **沖縄県** を選び、配布形式は **GeoJSON版** を推奨します。
- 今回実機確認した例（都道府県・年度によりファイル名は変わります）:
  - `A33-25_47_GEOJSON.zip`

  このGeoJSON ZIPは展開せず、そのままアップロードしてください。
- sheltermatchはファイル名から入力なしで **土砂災害** と自動判定します。Colabが同名ファイルを
  回避するために `A33-25_47_GEOJSON (1).zip` のようにリネームした場合も、ファイル名の先頭部分で
  判定するため問題ありません。
- 公式属性 `A33_001`（現象の種類）/`A33_002`（区域区分）がある場合は、公式コードリストの名称を
  そのまま使ってポリゴンごとに反映します。

  | A33_001（現象の種類） | A33_002（区域区分） |
  | --- | --- |
  | 1 = 急傾斜地の崩壊 | 1 = 土砂災害警戒区域(指定済) |
  | 2 = 土石流 | 2 = 土砂災害特別警戒区域(指定済) |
  | 3 = 地滑り | 3 = 土砂災害警戒区域(指定前) |
  | | 4 = 土砂災害特別警戒区域(指定前) |

  例:

  ```text
  土砂災害:急傾斜地の崩壊:土砂災害警戒区域(指定済)
  土砂災害:土石流:土砂災害特別警戒区域(指定済)
  土砂災害:地滑り:土砂災害警戒区域(指定済)
  ```

- 国土数値情報A33の公式仕様上、データ形状には面（Polygon/MultiPolygon）と線（LineString等）が
  存在します。sheltermatchではPolygon/MultiPolygonのみを区域判定対象とし、それ以外のgeometry type
  は独自に面へ変換するような解釈は加えず区域判定対象外として除外します（除外件数は
  「○件は区域判定対象外のgeometry typeのため除外しました。」と集約表示されます）。実際の利用時は、
  この集約ログで除外件数を確認してください。
- **国土数値情報は概略位置を示す参考データです。** 最新の指定状況や正確な境界が必要な場合は、
  沖縄県等の指定管理者（都道府県）が公表する資料を確認してください。

## 7. Notebookでの操作手順

1. 「利用者設定」セルで `ENABLE_HAZARD_CHECK = True` にする
2. 「ランタイム → すべてのセルを実行」
3. 要支援者一覧CSVをアップロードする
4. ハザードデータのアップロード画面で、必要なZIP・GeoJSONをまとめて選択する
5. 自動判定されたハザード種別をprint出力で確認する
6. 処理完了後、`assigned_shelters.csv` の内容を確認する

洪水・土砂災害・津波・高潮のデータは、同じアップロード画面で複数まとめて選択できます。例えば、

```text
A31a-25_47_10_GEOJSON.zip
A31a-25_47_20_GEOJSON.zip
A33-25_47_GEOJSON.zip
level1_1cm-30cm.zip
47007_takasiosinnsuisoutei_22itoman.zip
```

を一度に選択してアップロードできます。

## 8. 自動判定できないデータ

上記の洪水（A31a）・土砂災害（A33）・津波（level1〜7）・高潮（takasiosinnsuisoutei）のように、
ファイル名が既知の公式配布形式に一致する場合は、ハザード種別名の入力を求めずそのまま自動判定します。

ファイル名がどの既知パターンにも一致しない場合のみ、Notebookが次のように種別名の入力を求めます。

```text
'（ファイル名）' のハザード種別を自動判定できませんでした。
ハザード種別名を入力してください（例: 洪水, 土砂災害, 津波, 高潮。...）:
```

未知のファイルについて、sheltermatchが種別名を勝手に推測することはありません。入力が空欄の場合は
ファイル名がそのまま `hazard_type` として使われます。

## 9. 出力結果（`assigned_shelters.csv`）の読み方

ハザード関連の列は次のとおりです（`N` は候補順位の番号）。

- `resident_in_hazard` / `resident_hazard_types`
- `candidate_N_shelter_in_hazard` / `candidate_N_shelter_hazard_types`
- `candidate_N_straight_line_intersects_hazard` / `candidate_N_straight_line_hazard_types`

判定値の意味は共通です。

- `True` = ハザード区域内（境界上含む）、または直線が区域と交差
- `False` = 有効な座標で判定した結果、区域外
- 空欄（NaN） = 座標の欠損・不正等により判定できなかった（区域外という意味ではありません）

複数のハザードに該当する場合は、`hazard_types` 列に `洪水（その他の河川）;津波:0.01m以上0.3m未満`
のように `;` 区切りで保持されます。

**`straight_line`（直線）の列は、道路経路上の避難経路判定ではありません。** 要支援者地点と候補避難所
地点を単純に結んだ直線とハザード区域が交差するかどうかを示すだけで、実際に通行できる経路かどうかは
判定していません。

## 10. データの保管方針

- 国・県等から取得した公式GISデータ本体（GeoJSON・Shapefile ZIP等）は、このリポジトリへコミット
  しません。必要になった時点で公式配布元から取得してください。
- `test/` ディレクトリには、架空の要支援者CSVや実行結果CSVなど、個人情報を含まないテスト用データを
  置いて構いません。
- 実際の要支援者情報等の個人情報は、いかなる形式でもコミットしません。
- 公式データは年度更新や区域の追加指定により更新される可能性があります。過去に取得したZIPを
  プロジェクトの正本として扱わず、判定を行う都度、最新の公式データを取得し直してください。
