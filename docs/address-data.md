# 住所変換用ABRデータの取得・利用手順

この文書は、`address_geocode.ipynb`（住所→座標変換）で使用するデータについて、どこから取得し、どの
ファイルを選び、Notebookへどう投入し、結果をどう読むかをまとめた実務手順書です。実装の内部設計は
`docs/project-status.md` を参照してください。

## 1. 前提

- `address_geocode.ipynb` は、要支援者一覧CSV等の `address` 列を持つCSVへ緯度・経度を付与するための
  独立したNotebookです。**sheltermatch本体（`sheltermatch.ipynb`）には統合していません。**
- ABRデータ本体（CSV ZIP）はこのリポジトリへ保存しません。使用するたびに、公式配布元から取得して
  Notebookへアップロードします。
- 対象は沖縄県糸満市（地方公共団体コード `472107`）です。次の住所を変換できます。
  - **地番住所**（例: `糸満市字○○673番地2`）
  - **住居表示住所**（例: `糸満市○○町37番14号`、`糸満市○○2丁目32番2号`）
  - 上のどちらかの後ろに、施設名・建物名・部屋番号等の**方書**が付いた住所
    （例: `糸満市字○○927番地の2 ○○ホーム`、`糸満市○○町37番14号 ○○マンション 101号室`）

## 2. 取得元

- **アドレス・ベース・レジストリ（ABR）公式ダウンロードサイト**（デジタル庁）
  - <https://dataset.address-br.digital.go.jp/>

非公式ミラー・GitHub上のコピー・第三者配布データは使用しないでください。

## 3. 必要なデータ

### 地番住所用（必須）

| ファイル例 | 用途 |
| --- | --- |
| `mt_town_all.csv.zip` | 全国町字マスタ。住所から町字・`machiaza_id` を特定し、その町字が住居表示地域（`rsdt_addr_flg=1`）かを判定する |
| `mt_parcel_city472107.csv.zip` | 糸満市の地番マスタ。町字＋地番から `prc_id` を特定する |
| `mt_parcel_pos_city472107.csv.zip` | 糸満市の地番位置参照。`prc_id` に対応する代表緯度・経度を取得する |

### 住居表示住所用（住居表示地域の住所を変換する場合に必要）

| ファイル例 | 用途 |
| --- | --- |
| `mt_rsdtdsp_blk_pref47.csv.zip` | 住居表示-街区マスター。町字の中の街区（街区符号）の一覧。照合で「街区が見つからない」のか「住居番号が見つからない」のかを区別するために使う |
| `mt_rsdtdsp_rsdt_pref47.csv.zip` | 住居表示-住居マスター。街区符号・住居番号・住居番号2から住居を特定する |
| `mt_rsdtdsp_rsdt_pos_pref47.csv.zip` | 住居表示-住居位置参照。住居に対応する緯度・経度を取得する（**住居表示住所の座標はここからだけ取る**） |
| `mt_rsdtdsp_blk_pos_pref47.csv.zip` | 住居表示-街区位置参照。確認用に件数を表示するだけで、住所の座標には使わない（任意） |

住居表示データは**沖縄県単位**（`pref47`）で配布されています。Notebookはファイル名の `pref47` を信用せず、
CSV内の `lg_code` を見て**糸満市（`lg_code=472107`）の行だけを抽出**して使います。

住居表示データをアップロードしない場合も、地番住所の変換はそのまま行えます（住居表示地域の住所は
`residential_display_area` として保留されます）。

`472107` は糸満市の地方公共団体コード（全国地方公共団体コード）です。

## 4. 現在使わないデータ

`abr_post_code.zip` 等の郵便番号データは使用しません。取得済みであっても問題はなく、Notebookは列構成から
郵便番号データと認識した場合は無視します。

## 5. ダウンロード手順

1. ABR公式ダウンロードサイト（<https://dataset.address-br.digital.go.jp/>）を開く
2. **全国町字マスタ**のデータセットから `mt_town_all.csv.zip` 相当のファイルを取得する
3. **地番マスタ**・**地番位置参照（位置参照拡張）**のデータセットから、糸満市（`472107`）分のZIPを取得する
4. **住居表示-街区マスター**・**住居表示-街区マスター位置参照拡張**・**住居表示-住居マスター**・
   **住居表示-住居マスター位置参照拡張**のデータセットから、沖縄県（`pref47`）分のZIPを取得する
5. いずれのZIPも展開せず、そのまま保存する

公式サイトの画面構成・メニュー名は変更される可能性があります。上記はキーワード検索から対象データの
詳細ページを開き、ダウンロードするという大まかな流れとして参照してください。

## 6. Notebook側の扱い

- 「ABRマスター準備」セルで、上記のZIP（地番用3種類＋住居表示用4種類）をまとめてアップロードします。
  ZIPは展開せず、そのまま選択します。
- ファイル名ではなく、ZIP内CSVの列構成（`lg_code` / `machiaza_id` / `blk_id` / `rsdt_id` 等）からデータ種別を
  自動判定します。すべての列を文字列として読み込み、IDや番号の先頭ゼロ・空欄をそのまま扱います。
- 町字マスタ・住居表示データからは `lg_code=472107` の行だけを抽出します。Notebookには、抽出後の件数
  （住居表示-街区・街区位置参照・住居・住居位置参照）と、次の確認用の件数が表示されます。
  - 住居マスター・住居位置参照のキー重複件数
  - 住居マスターと住居位置参照の結合件数、位置参照が見つからない住居の件数
  - 座標欠損件数
  - （参考）街区位置参照で同じ街区に複数の位置がある街区の数
- 件数はABRの更新で変わるため、決まった件数と一致しなくても止めません。ただし、次の場合は曖昧な座標を
  作らないよう、処理を止めます（住所CSV変換セルも実行しません）。
  - 住居表示データの一部（街区・住居・住居位置参照のいずれか）が無い
  - 住居表示データに糸満市の行が無い
  - 住居マスターと住居位置参照を対応付けるキー（`lg_code, machiaza_id, rsdt_addr_flg, blk_id, rsdt_id,
    rsdt2_id`）が一意でない（重複を勝手に1件へまとめることはしません）
- 街区位置参照には、同じ街区について複数の位置を持つ行が実際にあります。住所の座標には使わないため、
  これは異常として扱いません。
- 「ABRマスター準備」セルを一度実行すれば、同じColabランタイムが生きている間は、住所CSVを差し替える
  たびにABR ZIPを再アップロードする必要はありません。「住所CSV変換・出力」セルだけを繰り返し
  再実行できます。

## 7. 共通住民CSVとの関係

住所データ（共通住民CSV）とABRマスタ（上記ZIP）は別のものです。

`address_geocode.ipynb` は、次の5列を持つ**共通住民CSV**を入力・出力とします（テンプレート:
[templates/residents.csv](../templates/residents.csv)）。

```text
resident_id,address,latitude,longitude,geocode_status
```

- 初回投入時に値が必要なのは `resident_id` と `address` だけです。`latitude` / `longitude` /
  `geocode_status` は空欄で構いません。
- `resident_id` は住民を一意に識別するIDです。空欄・重複がある場合、`address_geocode.ipynb` は
  どの行に問題があるかを示した上で処理を止めます（住所変換結果と避難所候補算出結果を紐づける
  結合キーのため）。
- **`address` は入力のまま出力します。** 方書を除くのは照合のときだけで、`address` 列は書き換えません。
- 変換後も列構成は変わりません。`latitude` / `longitude` / `geocode_status` の3列が、変換のたびに
  最新の結果で埋まる・上書きされるだけです。`normalized_address`・除外した方書（`ignored_suffix`）・
  住所の種類（`address_type`）等の確認用の情報は Notebook 上の表示にだけ使い、出力CSVには含めません。

列構成が変換前後で変わらないため、出力CSVは加工せずに次のどちらにも使えます。

- 住所を修正して、同じCSVを再度 `address_geocode.ipynb` へ投入する（再変換。全行を再評価し、古い
  `latitude` / `longitude` / `geocode_status` は最新の結果へ置き換わります。**手で入力した座標も
  上書きされる**ため、手入力は住所変換を終えてから行ってください）
- そのまま `sheltermatch.ipynb` の要支援者CSVとしてアップロードする

## 8. 住所の照合方法

### 共通の正規化

住所は照合の前に次のように正規化します（元の `address` は変更しません）。

- 全角／半角の統一（Unicode NFKC正規化）、ハイフン類（`－` `ー` `‐` `―` `−` 等）の統一
- 空白の除去（住所の途中の余分な空白にも対応）。ただし**数字と数字の間の空白は詰めません**
  （`673-2 101` を `673-2101` という別の番号にしないため）
- 丁目の漢数字（`一丁目`）を算用数字へ揃える（地番・番号の漢数字は桁の解釈が一意に決まらないため変換しない）
- 先頭の都道府県名・市名は省略可

### 町字の特定

入力住所の先頭と最も長く一致する町字を採用します。ABRの正式町字名が「字」「大字」で始まる場合は、
`字○○` / `大字○○` / `○○` のいずれの表記でも一致します（接頭辞の無い町字に「字」を付けた住所は
一致しません）。同じ長さで複数の町字に一致し、一つに絞れない場合は `ambiguous_town` とします。

町字マスタの `rsdt_addr_flg` によって、その後の照合方法が変わります。

### 地番住所（`rsdt_addr_flg` が `1` 以外の町字）

町字の後ろの番号を地番（`prc_num1` / `prc_num2` / `prc_num3`、1〜3段）として読み取り、地番マスタと完全一致で
照合します。`673` / `673番地` / `673-2` / `673番地の2` / `673番地2` / `673番2` / `673の2` は区切りの表記が違う
だけの同じ表記として扱います。`673` と `673-2` は別の地番です（前方一致で座標を決めません）。

### 住居表示住所（`rsdt_addr_flg` が `1` の町字）

町字（丁目を含む）の後ろの番号を、**街区符号**（`blk_num`）・**住居番号**（`rsdt_num`）・**住居番号2**
（`rsdt_num2`）として読み取ります。

| 住所の例 | 町字 | 街区符号 | 住居番号 | 住居番号2 |
| --- | --- | --- | --- | --- |
| `○○町37番14号` / `○○町37-14` / `○○町37番14` | ○○町 | 37 | 14 | （なし） |
| `○○2丁目32番2号` | ○○2丁目 | 32 | 2 | （なし） |
| `○○町37番16号の1` / `○○町37-16-1` | ○○町 | 37 | 16 | 1 |

住居表示-住居（住居位置参照と結合済み）と、町字・街区符号・住居番号・住居番号2の**完全一致**で照合し、
1件だけに一致した場合に限り、**住居位置参照の座標**を使います。

- 街区まで一致しても、住居番号まで一致しなければ `matched` にしません。**街区の代表点（街区位置参照）で
  代用したり、近い住居番号へ寄せたりはしません**
- 番号を補完・近似しません

#### 3段の番号（例: `○○2丁目36番7-201号 ○○コーポ`）

住居表示住所の末尾に部屋番号がハイフンでつながっている場合があります。一方で、ABRの住居番号2（`rsdt_num2`）が
使われている住所もあり、3段目が部屋番号なのか、ABRに未収録の住居番号2なのかは、番号だけでは確定できません。
座標は避難所候補の距離順位に使われるため、推測で一致させるより未変換を優先し、次の順で照合します。

1. **3段のまま完全一致を最優先します。** `36-7-201` を街区符号36・住居番号7・住居番号2 `201` として照合し、
   1件だけ一致すればその住居を採用します（方書の有無に関わらず同じです）
2. 3段目を部屋番号等の付加情報として除外するのは、次の条件を**すべて**満たす場合だけです（`matched`）
   - 元の住所から、空白区切りの方書（建物名等）を**実際に除外した**住所で照合している
     （例: `○○2丁目36番7-201号 ○○コーポ` → `○○2丁目36番7-201号`）
   - その住所の3段の完全一致が**0件**
   - 3段目を除いた住居（街区符号36・住居番号7・住居番号2が空欄）が、ABRにちょうど1件だけある
   - その住居の住居位置参照に座標がある
   - 同じ町字・街区符号・住居番号で、住居番号2を持つ住居がABRに無い（ある場合、3段目はABRに無い住居番号2の
     可能性があるため除外しません）
3. 条件を満たさない場合は除外しません
   - **方書の無い `○○2丁目36番7-201号`** は、3段の完全一致が無ければ `residential_number_not_found` のままです
     （`36番7号` へは寄せません）
   - 方書を除外しても、3段目を除いた住居が0件・座標なしなら `residential_number_not_found`、2件以上なら
     `ambiguous_residential` です
   - 街区の代表点（街区位置参照）や近い住居番号では代用しません

`○○町37番14号 101` のように、番号が `号` で終わった後ろに空白で部屋番号がある住所は、空白の位置で `101` を
方書として外した `○○町37番14号` がそのままABRに一致するため、3段目の除外には当たりません。

除外した3段目（`ignored_number`）、ABRで一致した住所（`abr_address`。例: `○○2丁目36番7号`）、除外した方書
（`ignored_suffix`）は、Notebook上の確認用の表示で確認できます（正式CSVの `geocode_status` は `matched` で、
列は増えません）。**除外した番号が本当に部屋番号等かを確認してください。**

この扱いは住居表示住所だけです。地番住所の `673-2-101` は3段の地番として照合し、方書があっても `673-2` に
短縮しません。

### 方書（施設名・建物名・部屋番号等）

まず住所全文で照合し、**見つからなかった場合だけ**、元の住所にある**空白の位置**で、右から順に後ろを
切り落とした候補で照合し直します。

```text
沖縄県糸満市字○○927番地の2 ○○特別養護老人ホーム 東棟   ← まず全文で照合（見つからない）
沖縄県糸満市字○○927番地の2 ○○特別養護老人ホーム          ← 空白の位置で切り落として照合
沖縄県糸満市字○○927番地の2                                  ← 一致したので採用（matched）
```

- 候補がABRと完全一致した場合だけ採用します。方書を除いたことで曖昧さを解消することはしません
  （曖昧な場合は `ambiguous_*` のままです）
- **空白の無い住所は切り詰めません。** `673-2-101` を `673-2` にするような「末尾だから部屋番号だろう」という
  推測はしません。方書は空白で区切って入力してください（住居表示住所の3段目も、空白区切りの方書を
  除外した場合に限り、上の「3段の番号」の条件を満たすときだけ除外します）
- 数字の直後の空白で、その後ろが**数字だけ**の場合（例: `673-2 101`、`673 2`）も切りません。番号の続きか
  部屋番号か判断できないためです（未変換になります）。`673番地2 101号室` のように `号室` が付く等で方書と
  分かる場合は、外して照合します
- 建物名と部屋番号の両方がある住居表示住所（例: `○○2丁目36番7-201号 コーポ○○`）は、空白の位置で建物名を
  外したあと、上の「3段の番号」の順序で照合します
- `address` 列は入力のまま出力します。方書を除いて照合できた件数と、除いた部分（`ignored_suffix`）は
  Notebook上で確認できます。**除いた部分が本当に方書かを確認してください**

## 9. geocode_status

変換できなかった行も削除せず、`geocode_status` 列で状態を確認できます。曖昧な住所を推測して
`matched` 扱いにすることはありません。

| geocode_status | 意味 |
| --- | --- |
| `matched` | 現在使用しているABRデータから住所（地番、または街区・住居番号）を一意に特定し、座標を取得できた（住居表示住所の3段目を部屋番号等として除外した場合を含む。「3段の番号」を参照） |
| `blank_address` | `address` が空欄だった |
| `town_not_found` | 入力住所の先頭と一致する町字が見つからなかった |
| `ambiguous_town` | 同じ長さで複数の町字（`machiaza_id`）に一致し、一つに絞れなかった |
| `parcel_not_found` | 地番住所: 町字は特定できたが、地番を読み取れない、または該当する地番が地番マスタに見つからなかった |
| `ambiguous_parcel` | 地番住所: 地番の候補が複数残り、一つに絞れなかった |
| `residential_block_not_found` | 住居表示住所: 町字は特定できたが、街区符号を読み取れない、またはその町字に該当する街区が見つからなかった |
| `residential_number_not_found` | 住居表示住所: 街区は見つかったが、住居番号（住居番号2を含む）が一致する住居が見つからなかった（3段目を除外する条件も満たさなかった） |
| `ambiguous_residential` | 住居表示住所: 同じ町字・街区符号・住居番号の住居が複数あり、一つに絞れなかった（3段目を除いた住居が複数ある場合を含む） |
| `coordinates_missing` | 地番または住居は一意に特定できたが、対応する位置参照データに座標が無かった |
| `residential_display_area` | 住居表示地域の住所だが、住居表示データがアップロードされていないため照合していない（住居表示データを使う通常の運用では出ない） |

`*_not_found`・`coordinates_missing` は「現在使用しているABRデータでは、住所または位置参照を確認できなかった」
という意味で、**その住所が存在しないとは限りません**（下記「変換できなかった住所の扱い」）。

### 変換できなかった住所の扱い

**100%の自動変換を目標にして、照合の条件を緩めることはしません。** 座標は避難所候補の距離順位に使われるため、
推測で座標を付けるより、未変換として残して職員が確認できるようにすることを優先します。

| 状態 | どういう住所か | 行わないこと |
| --- | --- | --- |
| `coordinates_missing` | 地番または住居はABR上で一意に特定できたが、対応する位置参照（座標）が取得できない | 推測した座標や町字の代表点等で補完しない |
| `parcel_not_found` | 町字は特定できるが、対象の地番を現在使用しているABR地番マスタで確認できない | 近い地番への補完や前方一致をしない |
| `residential_number_not_found` | 住居表示の街区までは確認できるが、対象の住居番号を現在使用しているABR住居データで確認できない | 街区の代表点や近い住居番号へ寄せない |

ABRで確認できなかった原因としては、ABRデータの更新時期、新たな付番、ABRへの未収録、位置参照データの未整備、
入力住所との表記の差異などが考えられます。ただし、どれに当たるかは現時点では確定できないため、
「ABRに無い＝新しい住所」とは扱いません。

未変換の行は、元データの住所を確認し、表記の誤りであれば修正して再変換します。ABRの更新で変換できるように
なる場合もあるため、ABRの新しいデータを取得したときに再変換して確認します（下記「10. データの更新と
再変換の手順」）。座標を個別に確認して手で入力する場合は、再変換で上書きされるため、住所変換を終えてから
最後に行ってください。

### 変換できない主な表記

- 方書が空白なしで番号に続く住所（例: `673番地2号室`、`37番14号101号室`）
- 方書の無い住居表示住所で、3段の番号がABRに無いもの（例: `○○2丁目36番7-201号`。3段目が部屋番号か確定
  できないため。建物名等が空白区切りで付いていれば、「3段の番号」の条件で照合します）
- 番号の後ろに空白を挟んで数字だけが続く住所（例: `673-2 101`。番号の続きか部屋番号か判断できないため）
- 丁目をハイフンで書いた住居表示住所（例: `○○2-32-2`。`○○2丁目32番2号` と書く）
- 地番・番号の漢数字（例: `六七三番地`）

## 10. データの更新と再変換の手順

### 保管の方針

- ABR公式CSV ZIPそのものは、このリポジトリへコミットしません。必要になった時点で公式配布元から
  取得してください。過去に取得したZIPをプロジェクトの正本として扱いません。
- 実際の住所CSV・変換済みCSV等、個人情報を含み得るデータは、いかなる形式でもコミットしません。
  前回との比較に使う変換済みCSVは、所属団体の規程に従って保管してください。
- `experiments/address_conversion_test_input.csv` は、個人情報を含まない検証用サンプルとして
  リポジトリ内に置いています。

### ABR更新時の再変換手順

ABRの公開データは更新されることがあります。決まった更新時期を前提にせず、次の手順で確認します。

1. 利用前、または定期的な確認の際に、ABR公式配布元（「2. 取得元」）で更新の有無を確認する
2. 現在使用しているものより新しいデータがあれば、「3. 必要なデータ」の各ZIPを取得し直す
3. `address_geocode.ipynb` で住所CSVを再変換する
4. `matched` / `coordinates_missing` / `parcel_not_found` / `residential_number_not_found` の件数を前回と比較する
5. 新たに `matched` になった住所を確認する（前回の変換済みCSVの `geocode_status` と比べる。住居表示の3段目や
   方書を除外して照合した行は、Notebookに表示される一覧で除外した部分を確認する）
6. 変換済みCSVを `sheltermatch.ipynb` へ投入し、`assigned_shelters.csv` と `sheltermatch_review.zip` を作り直す

2026-09-29 の確認で使用したABRデータは、2026年3月時点の公開データです。今後、公式配布元で更新を確認した
際に再取得します。
